# MoaWorks Subagent 파일럿 운영 환경

## 1. 목적

이 환경은 어울1이 설계 책임을 유지하면서 어울2에게 구현을 위임하고, 결과를 일관된 상태로 판정하기 위한 파일럿이다. 현재 단계에서는 Skill, Hook, Plugin으로 승격하지 않는다.

## 2. 역할

- 어울1: 설계, 기술 판단, 작업지시서와 간결 프롬프트 작성, 결과 판정, 독립 테스트, 최종 보고, 필요 시 직접 구현
- 어울2: 승인된 설계와 작업계획에 따른 구현, 기본 테스트, 정식 작업자 보고서와 구조화 결과 제출
- 신산님: 기능 범위, 요구사항, 중요 위험 변경 승인
- CLAUDE: 기존 방식의 독립 검증. Subagent 상태 흐름에 결합하지 않는다.

## 3. 실제 실행 흐름

1. 어울1은 승인된 설계서, 실행 계획, 작업지시서, 작업 프롬프트를 확정한다.
2. `scripts/moaworks-subagent-state.mjs init`으로 작업을 등록한다.
3. `dispatch`로 전체 문맥이 포함된 `handoff.md`를 생성한다.
4. 메인 Codex는 `spawn_agent`로 어울2를 실행하고 `bind-agent`로 반환된 agent id를 기록한다.
5. `wait_agent`로 작업 종료까지 기다린다. 중간 진행 메시지만으로 결과를 판정하지 않는다.
6. 어울2는 작업자 보고서와 `result.latest.json`을 제출한다.
7. 어울1은 `record`로 결과를 자동 분류하고 직접 diff, 실행, 화면, API, DB를 검수한다.
8. 재작업이면 갱신된 작업지시서와 프롬프트를 `rework`로 등록한 뒤 `send_input`으로 같은 agent id에 전달한다.
9. 예기치 않은 중단이면 `resume` 후 같은 agent를 재개한다. 재개가 불가능할 때만 현재 상태 전체를 새 agent에 전달한다.
10. 같은 `issueId`의 유효한 정식 실패 3회째에는 `close_agent`로 어울2를 중지하고 어울1이 단독으로 구현한다.

## 4. 결과 분류

### SUCCESS

- 구현과 개발자 기본 검증이 끝남
- 작업자 보고서와 구조화 결과가 있음
- 자동 상태는 `DESIGN_REVIEW_REQUIRED`
- 완료 판정은 어울1의 독립 검수 후에만 가능

### FORMAL_FAILURE

다음 필드가 모두 있어야 유효하다.

- 동일 문제를 식별하는 `issueId`
- 직접 원인과 증적
- 시도한 대안
- 현재 코드와 런타임 상태
- 남은 작업
- 구체적인 해결 제안
- 작업자 보고서 경로

명령 1회 실패, patch 실패, 테스트 도구 중단만으로는 정식 실패가 아니다. 유효하지 않은 실패보고는 실패 횟수에 포함하지 않고 재작업 대상으로 돌린다.

### INTERRUPTED

- 예기치 않은 프로세스 종료, 도구 일시 장애, 세션 중단
- 실패 횟수 증가 없음
- `RESUME_REQUIRED`로 분류하고 현재 상태부터 계속 수행

## 5. 쓰기 소유권

- 어울2 실행 중: 어울2만 제품 코드 수정 가능
- 어울1 검토 중: 양쪽 모두 제품 코드 수정 금지
- 1~2회 재작업 준비 중: 지시서만 어울1이 갱신하고 제품 코드는 수정하지 않음
- 3회 실패 인수 후: 어울2를 중지한 다음 어울1만 제품 코드 수정 가능
- 동시 수정은 항상 금지

## 6. 승인 경계

다음 세 가지가 바뀌는 경우에만 신산님 승인을 요청한다.

- 기능 범위
- 확정 요구사항
- 중요 위험 또는 운영 영향

구현 세부, 테스트 보완, 동일 요구 안의 버그 수정은 어울1이 판단하고 진행한다.

## 7. 파일

- `main-instruction.md`: 메인 대화 운영 지침
- `owoul2-developer-prompt.md`: 개발 Subagent 기본 프롬프트
- `task-envelope.template.json`: 작업 전달 계약
- `result-envelope.schema.json`: 결과 계약
- `worker-report-template.md`: 작업자 보고서 양식
- `runs/`: 실행별 상태와 인계 자료. Git 추적 제외
